# office-report

用户要"分析这张表、写通报、月报、分析报告、排名、对比上月、找出没达标的"时先读本技能：数据在 xlsx 里，成品多半是 Word（`create_docx`），也可能是 PPT 或回写表格。算数用 `analyze_xlsx`，写文档用 `office-docx`，改表用 `office-xlsx`。

## 铁律：数字只来自 analyze_xlsx

1. 合计、均值、排名、差值、占比、个数，**一律让 `analyze_xlsx` 算**，不要心算、不要手加、不要在工作区写脚本或临时文件。人工加十几个数十有八九会错，通报错一个数就是事故。
2. 第一次看一张表：只给 `relative_path` 调一次（默认就是 `profile`）。看返回的：
   - `header_row`：表头在第几行，标题行、说明行、合计行已经跳过；表头不对就传 `header_row` 重来，多个工作表用 `sheet` 指定。
   - 每列的 `type`、`unit`、`values`：月份、地市的实际写法就在这里，`where` 里照抄。`unit` 是 `%` 的列，数值按百分点给（96 就是 96%）。
   - `issues`：空白单元格、文本型数字、读不懂的文字，带单元格地址和所在行。
   - `notes`：被当作合计行、说明行排除的行。合计行确实要用时传 `keep_total_rows`。
3. **先限定期间再汇总**。表里常有十几个月，不限定月份就是把所有月加在一起。用 `where`：`{"col":"月份","op":"=","value":"2026-09"}`。月份可以写 `2026-09`、`2026/9`、`2026年9月`、`9月`。
4. 一次调用的 `queries` 里放多个查询（最多 12 个），每个起个 `name`，一次拿到通报要的全部数字。查询出错只影响它自己，看 `error` 改了重来。

## 问法对应的查询

| 要回答的 | 怎么写 |
| --- | --- |
| 全省概况 | 一个查询，`where` 限定月份，不写 `group_by`，`metrics` 放多个：`{"col":"投诉量","fn":"sum"}`、`{"col":"5G覆盖率","fn":"avg"}` |
| 排名前三、后三 | `group_by` 地市，`metrics`，`order_by` 指标名，前三加 `desc`，`limit` 3，要名次加 `rank` |
| 哪些没达标、超标 | 先 `read_xlsx` 读目标表拿到目标值和方向（不低于还是不高于），再 `group_by` 地市加 `having`：`{"col":"5G覆盖率","op":"<","value":96}` |
| 比上月、比去年同期 | `op` 写 `compare`，`period_col` 月份列，`current` 本期，`previous` 对比期，`group_by` 地市；结果列是 指标、指标`_prev`、指标`_change`、指标`_change_pct`，用 `order_by` 指标`_change` 取提升最多、下降最多 |
| 逐月趋势 | `op` 写 `pivot`，`pivot_col` 月份列，`group_by` 地市，一个 metric |
| 看明细、备注 | `op` 写 `rows`，用 `select` 选列，`where` 选行 |

不写 `op` 就是 `aggregate`（分组汇总）；`op` 还可以是 `profile`、`compare`、`pivot`、`rows`。`where` 和 `having` 里条件的 `op` 可用：`=`、`!=`、`>`、`>=`、`<`、`<=`、`in`（`value` 给列表）、`contains`、`blank`、`notblank`。

`fn` 可选：`sum`、`avg`、`min`、`max`、`median`、`count`、`count_distinct`、`first`、`last`、`weighted_avg`。`metrics` 里的 `col` 可以只写列名的一部分（只要不重名），`as` 改结果列名，`decimals` 控制小数位（默认 2 位）。`having` 和 `order_by` 用的是**结果列**的名字（看返回的 `columns`），`where` 和 `group_by` 用的是**原表列**名。`name` 只是给查询起的标签。

例：9 月 5G 覆盖率后三名并带名次，同时给出全省均值：

```json
{"relative_path":"data/月度指标.xlsx","queries":[
 {"name":"全省","where":[{"col":"月份","op":"=","value":"2026-09"}],"metrics":[{"col":"5G覆盖率","fn":"avg"},{"col":"投诉量","fn":"sum"}]},
 {"name":"后三","where":[{"col":"月份","op":"=","value":"2026-09"}],"group_by":["地市"],"metrics":[{"col":"5G覆盖率","fn":"avg"}],"order_by":"5G覆盖率","limit":3,"rank":true}
]}
```

## 口径和数据质量要写进通报

- 空白单元格**不计入**平均和合计（不是按 0 算）；文本型数字（如 `"93.8%"`）已按数值读取。返回里有这类提示时，把对结论有影响的写进通报最后的"数据说明"，并告诉用户，不要悄悄略过。
- 覆盖率、完成率这类率值，全省水平默认是各地市的简单平均；要按站点数、用户数加权，用 `weighted_avg` 并给 `weight`，并在通报里写明口径。
- 名次并列就如实写"并列第一"：`rank` 相同。出现 `tie at the cut` 提示，说明截取的名单边上还有并列项，要一起写上。
- 覆盖率类的差值单位是**百分点**（结果的 `units` 里是 `pp`），变化率才是 `%`；不要把"提升 0.87 个百分点"写成"提升 0.87%"。
- 没有数据的（`null`）写"无数据"，不要写 0；某地市只在一个期间有数据，`compare` 会在 `notes` 里列出来。
- 数字显示的位数跟原表一致：覆盖率两位小数加 `%`，件数、起数写整数。

## 写通报（Word）

骨架：标题 → 一句话结论（总体情况加最突出的问题）→ 全省概况（用表格）→ 排名 → 未达标和问题地市（表格，列出具体数字）→ 环比变化 → 下一步工作要求 → 数据说明。

- 每个地市、每个数字都来自查询结果，不凭印象写；没有依据的原因、措施不编，写"请各地市核实原因"之类。
- 下一步要求要对应前面发现的具体问题和具体地市，不写放之四海皆准的套话。
- 成品放在用户指定的目录（没指定就放 `reports/`），不要往工作区留脚本、草稿、临时文件。
- `create_docx` 写出的文件不能再读回来。所以数字在写进 Markdown 之前就要确认；写完用一次 `analyze_xlsx` 复核全省合计、前三后三这几个关键数。
- 通报要给领导看，表格不超过 6 列，一页放不下就拆；先写结论，再写数据。

## 分析之后还要改表（加列、标红、排名页）

按 `skill:office-xlsx` 做：先用 `save_as` 另存，不动原表。公式和条件格式按每列的 `stored` 来写（百分比存的是小数，月份是真日期，不是文本）；达标线从表里的"考核目标"这类工作表取，不凭印象写。排名页的数字取自 `analyze_xlsx`，写成固定值并注明口径。写完读回检查，汇报时说明哪些行因为缺数留空。

## 完成后向用户汇报

给出文件路径，说明用了哪个工作表、哪个月份、哪些口径假设（简单平均、合计行已排除），以及数据里发现的问题（空白、文本型数字、并列），请他核对。
