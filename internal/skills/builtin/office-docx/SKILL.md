# office-docx

用 `create_docx` 把 Markdown 写成真正的 Word 文档：工作报告、周报月报、会议纪要、方案、通知、说明书。

## 能做什么

正文用 Markdown 写，支持：`#` 到 `######` 标题、段落、`**粗体**`、`*斜体*`、`~~删除线~~`、行内代码、链接、多级 `-` 无序列表和 `1.` 有序列表、`| 表格 |`、围栏代码块、`>` 引用、`---` 分隔线。单独一行 `<!-- pagebreak -->` 另起一页。

`title` 是文件属性里的标题，不填就取第一个标题。已存在的文件默认不覆盖，要覆盖先问用户，或者换个文件名。

## 不能做什么

- 不能读取或原位修改已有的 .docx，也不能套用用户的 Word 模板、页眉页脚、目录和修订。用户要改一份现成的 Word：请他把正文贴过来，或者你按他的意思写一份新稿，保存成新文件名，并说明格式需要他自己在 Word 里再调。
- 不插入图片和图表。需要图表时，建议另做一个 xlsx 或 pptx（见 `office-xlsx`、`office-pptx`）。
- 旧的 .doc 先请用户另存为 .docx。

## 写之前

先确认：谁看、用途、篇幅、有没有固定格式要求（公文、公司模板）。有固定格式而你无法满足时，直接说明。事实和数据以用户提供的为准，没有的不要编，留"待补充"。

论文、研究报告、技术报告、可行性分析这类长文：先读 `skill:office-paper`（结构、数据和引用怎么写），再回到这里按工具的限制生成。

## 常见文档的骨架

- **周报**：本周完成（每条一个结果，带数字）→ 下周计划 → 问题与风险 → 需要协调的事项。
- **月报、季报**：一句话结论 → 关键指标（用表格）→ 做了什么 → 问题和原因 → 下一步。
- **会议纪要**：时间、地点、参会人 → 议题 → 结论 → 待办事项（用表格：事项、负责人、完成时限）。
- **方案**：背景与目标 → 现状问题 → 方案内容 → 实施步骤与时间 → 资源与风险 → 预期效果。
- **通知**：标题 → 事由 → 具体要求 → 时间和联系人。

## 写作规则

- 结论放前面，第一段就让读者知道要点；标题层级不要跳级（别从 `#` 直接跳到 `###`）。
- 一个段落一件事；列表项保持同一种句式；表格不超过 6 列，数据对齐要有单位。
- 多页的长文档在章节之间用 `<!-- pagebreak -->`，但不要每节都分页。
- 中文文档用中文标点，数字和单位之间保持一致写法（如"98.6%""12 万元"）。

## 完成后

告诉用户文件路径、大概页数范围（按内容估计，不要说成精确页数）和需要他核对的地方（人名、日期、数据）。你没有 Word 可以预览，不要声称"已检查排版"；可以说明表格、标题、列表都已经按 Word 的样式生成。
