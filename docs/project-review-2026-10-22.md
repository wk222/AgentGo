# 工作台交互与项目审查（2026-10-22）

## 本轮修复

- 标题栏工作台按钮固定名称，选中高亮，只控制显隐，恢复原内容及对话布局。场景 Tab、导航前后退不再强制改变布局；工作台工具栏提供放大/还原和收起。仅代码一个场景时隐藏重复的外层标签。
- Windows 后台语言服务创建进程时使用 HideWindow 和 CREATE_NO_WINDOW。Powernap v0.1.6 没有进程配置钩子，因此只在 internal/powernaplsp 保留其 MIT 授权的客户端源码副本并加窗口控制，协议、配置、传输仍使用原依赖。Python 校验/执行与 Docker 检测/运行也设置后台启动。
- 无效工作区回退到 dataDir/workspace；不再把整个应用数据目录当作工作区。
- 切换工作区和回退时，同步扩展引擎 Workspace，防止技能版本导出/恢复指向旧目录。
- 动态工具两条本地执行路径及 Docker 捕获输出每路最多保留 1 MiB，超限明确标记，仍排空管道。保留既有 90 秒超时。

## 验证

- 浏览器交互覆盖固定按钮名及选中状态、Tab 不变布局、收起保留场景/分屏、放大后收起恢复。
- Windows 进程标志测试验证隐藏窗口同时保留其他已有进程标志。真实 gopls 代码工具测试通过。
- 工作区回退隔离、扩展引擎重绑定、输出截断及现有动态工具安全回归。

## 仍需后续处理

1. 首次发送前的工作区快照仍可能耗时；后续未变化的快照已复用内容，不再重新读取整份文件。首次扫描仍需继续实测优化。
2. 上下文已补工作区规则及召回缓存、分层压缩、持久于运行状态的恢复检查点与预算修正；详情见 [上下文压缩说明](context-compression-2026-10-22.md)。
3. 前端 IPC 契约仍为手工维护；通用超时包装不等于取消后台操作，应增加契约校验及明确取消语义。
4. 扩展版本恢复涉及多个存储和文件，尚不是完整事务；并发修改与失败后的跨存储恢复仍需专门设计。
5. Docker 不可用时仍降级为当前用户权限的本地执行。环境过滤和窗口隐藏不提供操作系统隔离。

本次是针对执行、工作区和主要交互路径的审查，不代表所有功能都经过完整端到端验证。
