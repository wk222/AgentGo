# WeKnora 吸收实施记录

## 第一批：文档来源与安全续读

已实现代码：`internal/tools/docparser.go`、`docparser_source.go`。这是文档证据链的解析入口；持久索引、回答引用注册及 UI 原文定位尚未接入。

- `parse_file` 返回 `source.path / sha256 / parser_version / revision`。revision 绑定原文件哈希、解析契约版本和完整解析文本，避免同一原文被不同解析结果误续读。
- `source_spans` 的 `start/end` 是完整解析文本中的零起始 rune 半开区间；对应当前返回窗口时，应减去 `offset` 并裁剪到窗口范围。它不是原文件字节位置。
- PDF 保留真实页序，包括中间没有文本的页面；没有文本的页继续返回扫描件提示，不制造证据。
- XLSX 改为遍历全部工作表，保留表头和原始行号，包括稀疏行。原先的 Eino 默认解析只读首表并把首行当作不返回的表头。`sheets` 表示工作表数，`pages` 仅用于 PDF。
- DOCX 只标 `parsed_text_only`，不把解析文档数当作页码。文本文件标 `decoded_text`，偏移对应解码后文本。
- 默认每次返回 8000 字符，上限 32000；`char_count` 是本次返回量，`total_chars` 是全文长度。用 `next_offset` 续读，并携带 `expected_revision`（推荐）或 `expected_sha256`（只校验原文件）拒绝版本变化。
- 继续使用原有工作区路径授权；自定义解析器输出不冒充原文位置，并检查命令运行期间原文件是否变化。

调用示例：

```json
{"relative_path":"report.pdf","limit":8000}
```

下一次将返回的 `next_offset` 与 `source.revision` 放入 `offset`、`expected_revision`。

行为变化：旧调用默认拿全文，现在拿有续读入口的窗口；Excel 会覆盖其他工作表与表头。扫描 PDF 仍不自动执行 OCR。窗口读取当前仍重新解析文件，尚未引入缓存；不能据此声称重复读取的总耗时已下降。

验证：`go test ./internal/tools ./internal/arch -count=1` 通过；新增真实注册工具调用测试另行通过。覆盖重复 PDF 文本与空白页、XLSX 多工作表/表头/稀疏行、中文与 emoji 窗口拼回全文、默认限量、文件修改后的续读拒绝、非法窗口与工作区越界。未运行真实模型或桌面 UI 验收。

### 结构化分块预览已接通

开启现有 `AGENTGO_DOCCHUNK` 插件后，`parse_file` 可传 `preview_chunks=true`，可选 `chunk_size`（默认 512，范围 128–2048）。预览在完整解析文本上构建，再选取与返回窗口相交的块，保留跨窗口一致的 rune 范围、块 ID、标题上下文、父子引用和页/行来源。正文只返回一份，不在每个块里重复。

块 ID 绑定来源版本、类型、范围和标题；一次最多预览 32 个子块，另给 `next_preview_offset` 读取后续块的元数据。`next_offset` 仍表示正文续读位置。分块器缺失/停用时明确返回 `chunk_preview.status=unavailable`，不会伪造结构。插件停止时撤销注册表绑定，保留原记忆分块回落。

新增了递归/启发式回落块的标题上下文补全，依据原文位置扫描，忽略代码围栏内的伪标题，不改正文和偏移。注册表通过数据契约接插件，tools/memory 不直接导入 docchunk；架构守卫保持生效。

覆盖验证：真实运行时插件挂载与停止、父子关系、完整文档偏移、重叠窗口 ID 稳定、PDF 中间空白页映射、无插件降级、无效来源范围拒绝、代码围栏内标题隔离。

本节取代此前按功能逐项扩展的施工顺序。当前判断：**还有 4 项值得确定投入，另 2 项只在真实任务触发后投入**。前两项先把已有能力做完整，不继续扩大功能面。本节为计划，不代表新增能力已实现。

AgentGo 的主线是本地优先、能执行任务的桌面智能体：Eino 统一执行，会话/审批/恢复共享状态，结果可核对，重复任务能沉淀为工具、工作流与 Inner App。吸收文档和网页机制应服务这条主线。

- 每项在修改前记录基线、验收任务与回退方式，完成后检查是否增加状态所有者、后台进程和配置项。收益不足或维护成本过高则撤回该实现，不继续追加开关补救。

## 本轮新增：回答引用与原文快照

- `BindRunContext` 创建内存证据表，嵌套代理共享，同一进程的新执行和不同会话相互隔离。上限 128 条 / 2 MiB，满额后新读取不生成引用，不驱逐已发出的引用。
- `parse_file` 和 `web_fetch` 在成功读取后登记**实际返回的字符窗口**；网页登记发生在批次预算截断之后。返回 `citation.id`、来源、版本、全局 rune 范围；文件另带 PDF 页码 / XLSX 表名原始行号。
- 通用 Eino 中间件提示模型使用 `[[ev_…]]`。`read_evidence` 可在本次执行内回读不可变的片段，文件被改写也不会把旧引用悄悄换成新内容。暂停后另起的恢复执行如无原记录，需要重读来源；不是持久证据库。
- 对话界面只从当前用户轮次中、回答之前的成功来源工具结果解析引用；普通文本、搜索摘要、失败结果、损坏 JSON、来源/版本/范围不一致的记录均不能激活引用。未知 ID 显示“来源不可用”。流式正文与完成正文使用同一规则。
- 点击“来源”展示读取时的原文快照、来源、版本和页/行位置；DOCX 只显示解析文本位置。源码内容按文本显示，来源路径和 URL 不触发文件或网络操作。代码块、行内代码、已有链接中的引用语法保持原样。

这是来源追溯，**没有验证模型陈述是否被片段支持**，也没有实现 PDF 原生阅读器的页内高亮、文档更新后记忆索引的失效清理或浏览器登录态操作。

2026-10-28 的版本依赖前端保留完整工具结果，跨重启引用尚未接入；2026-10-29 已补齐会话快照存储，见下节。升级前没有保存的来源无法补回，仍显示“来源不可用”。

验证覆盖真实注册工具的读取/回读、Unicode 范围、会话/执行隔离、容量上限、来源修改后快照稳定性、网页共享预算与前端来源解析。桌面点击和真实模型选工具仍需实测；本次 UI 自动化通道报告 native pipe / browser access host 不可用，未取得视觉验收。

## 2026-10-29：A/B 收尾实现

### A：会话拥有引用快照

- 将原 tools 内的证据数据与运行期注册表移到无存储依赖的 `internal/evidence`，由 tools 与 core 真实共享。tools 保留适配入口，只有一个注册实现。
- `Transcript.Begin` 和审批恢复路径绑定快照保存回调；成功读取生成引用前，将快照写入已有 `chat_messages`，类型为 `source_evidence`。不增加存储服务、全局缓存或后台进程；每次执行仍受 128 条 / 2 MiB 限制。
- `es_…` 是绑定来源、版本、范围和内容的稳定快照身份；`ev_…` 是当前执行的引用句柄。历史行保存当时句柄到快照的关联，重新加载仅恢复导航，不把旧句柄注册进新执行。
- 前端把历史快照映射到已有来源展示路径，保留原始 JSON，避免通用文本清洗修改原文。模型历史和迁移历史继续排除这种非文本行。
- 会话删除沿用事务清理，分叉沿用会话记录事务复制。删除原会话不影响分叉内的快照。保存失败时不发出无法持久化的新引用；读取仍可返回正文。

### B：同一来源的显式原子换版

- 复用已有 `learn_document`，增加 `operation=replace|delete`（默认 replace）及 `expected_revision`，没有新增工具入口或任务队列。老的 `QueueLearning(document)` 转发同一实现。
- replace 接收同一稳定 source 的**完整供给文本**，最多 64000 字符；按现有 token 预算分节，在一个 SQLite 事务里保存新节、提取任务和当前版本，并撤回旧节。相同有效内容重试不重复排队。
- 旧节撤回复用现有触发器：取消任务、归档来源派生的候选记忆，并更新已有记忆/摘要树修订。混合召回已有 SQLite 回查继续过滤旧向量候选。独立用户记忆及其他来源/来源会话保持独立。
- 每次重新激活使用新的来源 generation，提取器仍在写入事务中核验来源。A→B→A 不复活旧任务；删除生成新的版本令牌，删除前准备的带旧 expected_revision 的导入不能重新激活来源。
- 新版本创建失败时整个事务回滚，旧版本仍可用；部分分节、取消标记和派生记忆归档均不会泄漏出失败事务。兼容清理旧 `source#section-N` 来源，只匹配数字后缀。

使用示例：

```json
{"source":"report.docx","operation":"replace","text":"完整读取后的文档正文","expected_revision":"上次返回的 revision"}
{"source":"report.docx","operation":"delete","expected_revision":"当前 revision"}
```
