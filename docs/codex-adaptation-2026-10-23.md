## 本轮实现

### 1. 内部上下文有独立来源标记

sessions.ContextMessage / ExtraContextKind 标记宿主生成的摘要、参考状态和反馈。普通用户正文不再通过 [System Summary] 等前缀决定类型。附件补全与当前用户请求保护使用同一标记，图片不会因为用户引用这些前缀而被忽略。

历史中没有元数据的用户文本继续作为用户文本处理；不通过不可信正文猜测旧消息来源。

### 2. 工具历史按连续调用组修复

每个 assistant 工具调用只能匹配其后连续 tool 消息中的返回。丢弃提前、跨组、重复和孤立返回；同组重复调用 ID 只保留一次。不同完整轮次复用 ID 按各自组匹配。没有结果的调用补充确定性的、仅用于提示的“结果不可用”消息，明确执行及副作用未知，重试前应检查实际状态。

协议修复先于裁剪和恢复记忆生成，防止丢弃的错误返回换个路径进入历史摘要。保留真实的空工具结果，避免将空返回误判成未完成。不会修改原始消息对象或实际执行记录。

旧检查点文案统一改为“工具调用轨迹（不代表完成或成功）”，避免与新的恢复记忆矛盾。

### 3. 稳定规则与动态参考状态分开

系统前缀保留规则、长效任务与隔离要求。摘要、召回记忆、工作流状态、近期工作区和上下文整理记录后置为带元数据的参考消息，并在下一次编译时重建，不重复追加。

工具输出默认不会仅因为变旧而改写；只有显式预算压力路径才做历史摘录。压缩、规则修改和历史窗口裁剪仍可能改变提示前缀。这里验证的是消息稳定性，没有声称内网网关的缓存命中率或响应速度已经达到某个数值。

记忆日记和异步摘要过滤宿主参考消息，防止把这些数据反复记录成用户原话。

### 4. 模型目录驱动的上下文预算

LLMConfig / LLMSettings 支持 context_window 与 max_output_tokens。私有兼容层仅在 API 地址精确匹配其当前运行的本地代理、模型 ID 存在于其目录时自动提供窗口与输出上限，不向其他同名模型套用参数。自定义端点可在配置中提供这两个字段；未知窗口保留既有策略，不猜模型规格。

可用输入预算 = 模型窗口 - 输出预留 - max(512, 窗口的 2%)。窗口已知、输出上限未指定时使用 min(4096, 窗口的 1/4) 的生成预留，并将同一上限用于实际模型请求。Chat Completions 和 Responses 两条模型路径均带上输出上限。

Canvas 仍决定执行策略与期望上下文规模；模型限制只收紧预算，不替换会话模式。摘要触发阈值、每轮裁剪以及最终检查使用一致的预算。工具 schema、多模态和受保护的框架提醒均计入估算。最终仍超出已知模型输入预算时，在调用上游前返回可理解的错误，不静默截断当前请求与规则。

估算不是精确 tokenizer；模型目录本身也需要正确。窗口限制以当前选中模型为依据，不代表已经验证所有第三方回退模型的窗口。

### 5. IPC 调度、超时和取消

移除无关调用共用的全局串行队列。读取与交互操作直接执行，其余操作按方法分别排队；同一方法仍保持顺序。显式超时直接用于真实调用，不再套用隐藏的 15 秒默认超时。文件夹选择、登录、模型测试和版本操作各有合适的默认等待时间。

保留 Wails CancellablePromise；超时请求 cancel，并阻止运行时加载过慢后再启动已经过期的操作。TestLLM、GetCreationCenter、ExtensionVersions 接收 Wails 注入的 context，长请求可以响应绑定取消。

超时表示已请求取消，不表示已回滚。已经提交的写入、独立的引擎任务和 OIDC 登录流程仍需各自的取消/状态协议，前端不自动重试有副作用的操作。

### 6. 回归配套

补齐 powernaplsp / processutil 的架构层级登记。更新旧测试中仍期待 focused 在 60000 tokens 才摘要的过时断言（当前策略为 12000），以及把召回记忆必须放在系统消息中的旧布局断言。
