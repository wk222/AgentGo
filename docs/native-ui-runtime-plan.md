# AgentGo 自有 UI 与统一执行融合计划

日期：2026-10-07。状态：计划阶段，未开始实现。

目标：复用已有自有 UI，让会话、编码、记忆、工作流、任务及插件围绕同一任务自然协作；桌面、Crush TUI 和无头入口共享上下文、审批、执行事件与恢复语义。

本计划接续 `deep-fusion-plan.md` 和 `codex-source-gap-audit.md`，保留已交付的插件宿主、生命周期、工作区治理、运行日志和审批中继。UI 改造与执行融合分阶段交付，不重新开始底层架构。

## 1. 已确认事实与路线

- 当前 `frontend` 使用 React/OpenSumi，入口为 `src/browser/index.ts`，布局为 `layout-config.ts`，AI 后端适配为 `render-app.ts`。
- 原 UI 完整保留在 `frontend-legacy`：Vue 3/TSX、Naive UI、Monaco；已有 App、ChatPanel、useChat、MemoryPanel、WorkflowEditor、任务/能力/技能/应用视图及代码工作区。
- OpenSumi 可通过 LayoutConfig、layoutComponent、ComponentContribution 和 SlotRendererContribution 定制布局、视图及插槽渲染。官方文档：[自定义视图](https://opensumi.com/zh/docs/integrate/universal-integrate-case/custom-view/)、[布局模块](https://opensumi.com/zh/docs/develop/module-apis/layout/)。实际 API 以仓库锁定的 3.9.0 版本为准。
- OpenSumi 的扩展点可解决布局问题，但不会自动提供 AgentGo 的任务状态与上下文语义。

**推荐方向：AgentGo 自有 UI 为主，复用旧 Vue 界面的组件和业务视图；代码工作区使用可替换适配器，首个实现复用已有 Monaco，OpenSumi 作为按需增强选项。**

这是默认实施方向，不宣称旧 UI 已可直接替换当前生产入口。N0 先验证旧组件的构建、数据和 IPC 兼容性，再决定切换。

| 方案 | 适用情况 | 本轮决策 |
|---|---|---|
| 自定义 OpenSumi 主布局 | 编辑器/调试/扩展生态是产品主轴，愿意迁移旧 Vue 视图 | N0 只核查必要能力和成本，保留备选 |
| 自有主界面 + 可替换代码工作区 | 会话、任务、记忆、工作流同等重要，已有可复用 Vue UI | 默认推荐 |

不把整套 OpenSumi 当普通 Vue 组件直接嵌入。若启用 OpenSumi 工作区，先验证独立挂载或同源隔离载体，明确文档同步、尺寸、焦点、快捷键、鉴权与释放契约；仅在收益明确时采用。

## 2. 用户体验目标

默认界面围绕当前会话和任务，用户可以直接表达目标、随时补充约束、查看修改、批准动作并继续执行。

```text
┌────────项目/会话────────┬────────当前任务───────────────┬────按需工作区────┐
│ 项目与会话列表         │ 用户目标与补充输入            │ 文件/编辑器/diff │
│ 新建会话               │ 执行进展与必要说明            │ 终端/验证结果    │
│                        │ 工具活动（默认简洁）          │ 工作流/产物      │
│ 功能入口               │ 审批/问题（需要时出现）       │                  │
│ 任务/记忆/工作流/应用  │ 最终结果与可打开的产物        │ 可收起/独立展开  │
│ 设置与插件管理         │ 输入框：补充、纠正、停止      │                  │
└────────────────────────┴──────────────────────────────┴──────────────────┘
```

- 会话全宽、会话+工作区、工作区全宽三种布局切换；窄窗口的辅助区使用抽屉。
- 活跃工具显示简短动词和对象；完成后默认折叠，保留输出、差异和错误详情。
- 中途输入明确区分“已接收”“已纳入下一步”和“开始新任务”，不能假装模型已经采纳。
- 审批在当前任务中显示拟执行动作及相关差异；解决后更新同一条记录，不重复弹窗。
- 修改、测试结果和产物可以从会话直接打开工作区。失败仍可继续修复，界面不把一段回复当任务完成。
- 记忆、工作流、任务、能力、技能、应用通过清楚的入口访问；普通用户界面不显示服务拓扑和协议参数。

## 3. 两层契约

### 3.1 UI 客户端契约

建立与 Vue、React、Wails 无关的 RuntimeClient，明确操作与订阅：

- Session：创建、列表、打开、恢复和读取历史。
- Run：开始、补充输入、取消、状态及事件订阅。
- Decision：审批和问答，绑定对应 session/run/item/request。
- Workspace：打开文件、读取差异、文档版本及进程交互。
- Capability：查询可用能力和贡献视图，配置变化后刷新。

沿用现有身份字段，并明确 session/run/step/tool-call/request 的归属。事件携带唯一 ID、序号与版本；瞬时 token 与已提交事实分开。客户端按序号去重和重连续读，最终状态由服务端提供。

客户端维护统一的事件 reducer。组件显示 reducer 投影，不能自己恢复 agent、决定工具风险或拼接模型历史。传输可使用 Wails 或鉴权本地连接，语义一致。

### 3.2 执行与上下文契约

- 所有主要入口经过统一 RunService；旧 SendMessage、SendMessageStream 作为兼容入口转发。
- ContextCompiler 在服务端从权威会话事实生成模型输入，不由 GUI/TUI 决定历史范围。
- 工具调用与结果保持配对；保留用户约束、未决任务、附件身份及验证证据。
- 实际请求预算包含工具 schema、参数和多模态开销；压缩后明确保留约束，报告记录实际删改。
- 初次执行、审批恢复、问题回复恢复共用事件接收器、日志提交和取消管理。
- 活跃运行拥有输入队列；采纳回执绑定真实消费步骤。
- 长进程通过同一能力支持启动、等待、stdin、输出和终止，不建立独立审批策略。

界面与执行服务分别可替换；“像 Codex 一样自然”以连续任务操作是否成立来验收，不以外观相似或接入更多工具代替。

## 4. 实施阶段

### N0：复用核查与界面决策（先做）

- [ ] 保留当前工作树，记录旧/新前端构建与原生启动基线，不覆盖有效数据和产物。
- [ ] 在预览中检查旧 UI 与当前 OpenSumi 的实际布局，列明功能入口、数据依赖和已失效 IPC。
- [ ] 建立组件复用清单：可直接复用、仅需新数据适配、需要重做。
- [ ] 核查 Wails/Electron 构建入口、资源嵌入、双入口切换与回退方式，暂不更换默认界面。
- [ ] 记录必需的 OpenSumi 能力：编辑/导航/LSP/终端/调试/扩展，区分已有 Monaco 能覆盖的功能。
- [ ] 用一个可运行的会话+文件+差异原型验证推荐路线；OpenSumi 载体仅验证必要兼容项。

验收：实际预览、可复查清单与明确路线。若旧组件大面积不可复用或必要编辑器能力缺失，再采用 OpenSumi 自定义主布局；不同时维护两套产品主界面。

### N1：统一运行客户端，先打通一条真链路

- [ ] 定义 RuntimeClient 与事件 reducer，实现真实 session ID、start/subscribe/cancel/decision。
- [ ] 修复 OpenSumi 同步伪流式入口；新 UI 同样使用真实事件流。
- [ ] 旧运行入口转发统一执行服务，日志、持久化与事件发布只有一个权威路径。
- [ ] 初次执行与审批续跑都提供逐步文本/工具/状态事件；明确暂停段和最终终态。
- [ ] 用确定性执行器验证乱序、重复、重连、连续审批与取消；再用已有真实模型配置验证一条修复链。

验收：自有 UI 与 Crush TUI 看到同一个任务、同一审批状态及工具结果；恢复后继续实时显示，重复用户操作不重复执行副作用。

### N2：重建任务主界面，复用旧业务视图

- [ ] 按目标布局复用 App、ChatPanel、会话列表和辅助工作区；旧 useChat 逐步改为 RuntimeClient 适配。
- [ ] 输入框支持运行中补充、停止、附件及明确的采纳状态。
- [ ] 活动列表区分说明、工具、审批、问题、文件变化、验证和最终产物。
- [ ] 工作区打开动作保留当前会话和任务；支持分栏、全宽、抽屉与键盘操作。
- [ ] 保留旧主题和品牌可复用部分，统一间距、字体、空态、错误态与加载态。

验收：浏览器预览与原生窗口均可操作完整链路；至少检查 1440、1024、768 宽度、长回复、错误、审批和取消。视觉检查必须看实际渲染，静态源码和 mock 不能代替原生 IPC 验收。

### N3：统一历史、上下文与中途输入

- [ ] 消除 desktop 固定会话及客户端选择历史；ContextCompiler 为全部入口生成同源输入。
- [ ] 将工具事实与附件纳入历史投影，修复按消息条数截开调用组的风险。
- [ ] 将预算检查接到实际窗口压缩，覆盖工具 schema 并保留任务约束与待办。
- [ ] 建立输入队列：排队/已采纳/无法采纳的事件；失败和取消时保留用户尚未消费的输入。
- [ ] 长任务压缩后继续执行；任务已终止时的新输入按明确规则开始下一回合。

验收：跨回合不丢约束；GUI/TUI 在同一事实序号生成等价模型输入；压缩后工具配对完整；执行中纠正范围在采纳回执之后影响后续动作。

### N4：代码工作区成为能力视图

- [ ] 建立 EditorAdapter：open/reveal/selection/diff/dirty/version/dispose；先复用旧 Monaco。
- [ ] 统一工作区与文档身份。未保存内容和磁盘变更冲突明确提示，禁止静默覆盖用户编辑。
- [ ] agent 文件修改后视图更新；编辑器选择与文件附件明确进入当前任务上下文。
- [ ] agent 进程与可见终端通过同一进程服务协作，支持长命令输出、输入和取消。
- [ ] OpenSumi 若启用，只承担经过 N0 确认的增强能力；主会话、审批和任务状态由自有 UI 管理。
- [ ] LSP 生命周期、诊断来源与未保存文档分析一致；多实现不能为同一服务重复起进程。

验收：修改→差异→审批→应用→测试全部可追溯；dirty 文档冲突可恢复；换工作区和关闭面板释放资源；编辑器与 agent 使用同一工作区。

### N5：原有功能与插件按任务融合

- [ ] 记忆：浏览、来源、作用域、搜索、修正；能从任务查看使用了哪些记忆。
- [ ] 工作流：独立设计画布；运行过程回到统一任务事件，可从会话打开画布及节点结果。
- [ ] 任务与调度：显示真实状态、产物、失败和待处理决定；使用相同执行服务。
- [ ] 能力/技能/应用：区分用户入口与模型可用能力，按探测结果展示，禁用时给明确原因。
- [ ] 定义 UI 贡献点：导航、任务附件、产物查看器、工作区面板、设置页；贡献拥有 Scope，可装卸。
- [ ] 前后端插件状态保持一致；面板关闭不等于取消后台任务，卸载需处理活跃资源和未决决定。

验收：上述功能均有真实可达入口；不是空壳视图或新建第二套数据。装卸不会留下菜单、监听器、审批或重复执行器。

### N6：工程任务验收与默认切换

- [ ] 固定任务集：跨文件修复、失败测试再修复、两次审批、执行中纠正、长进程、断线重连、压缩后继续、dirty 文档冲突、工作流与记忆协同。
- [ ] 同一模型设置与初始工作区，对比改造前后成功率、耗时、消耗、用户介入和错误恢复。
- [ ] Codex 参考运行单独记录模型/工具差异；未经公平对照不宣称工程能力相当。
- [ ] 回归关键 Go 包、前端类型检查/构建、原生打包与视觉操作；已有失败独立记录。
- [ ] 验收通过后切换默认入口；保留可用回退入口，数据库迁移有备份和版本标记。

验收：任务真实完成、证据完整、所有入口一致；至少有完整原生操作记录。旧 UI 组件被复用不等于旧执行路径继续存在。
