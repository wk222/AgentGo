# 摘要过多时继续树形合并（2026-10-24）

本轮目标始终是**模型上下文中的记忆 Token 上限**。之前把问题转成磁盘容量管理是错误理解；本轮不以磁盘容量作为验收目标。

## 从研究中采用的机制

参考 [MemForest / MemTree](https://arxiv.org/html/2605.23986v3) 的有界分支、父节点概括子节点、逐层向上合并、局部语义刷新和粗到细检索。本轮也读取了官方 src/build/summary_manager.py 的摘要调度代码。

采用默认分支数 8、单节点摘要最多 128 个统一估算 Token。这是 AgentGo 的工程默认值，不是论文保证的最优参数。不声称完整复现另一篇 MemForest 的 KMeans、最大生成树或 AGPR。

## 已实现的上下文行为

- 一条主题分支内部先按时间顺序组织记录，再逐层合并；主题分支数量过多时，主题根继续归并，直到形成一个总根。层数随需要增长，不限定为固定 L0/L1/L2。
- 父节点最多 8 个子节点。父摘要引用全部子节点，保留可展开的节点 ID；原记录内容保持独立。
- 模型输入选择的是一组“树的切面”：用父摘要覆盖整段子树，展开时替换为其全部直接子节点，不同时放入父节点和后代，不丢掉未展开分支的入口。
- 召回命中通过 record → ancestors 路由提升相关分支的展开优先级。预算很小时只保留高层摘要或根入口；目录本身也计入预算。
- 渲染时按当前预算分配摘要正文，单节点上限不代表必须用满。节点 ID、计数、导航提示和摘要一起按统一估算器计量。
- browse_memory 新增 action=tree：空 node 获取根；指定返回的 node ID 展开；叶子含 record_id，可用 action=read 读取证据。关键词检索继续绕过摘要导航。
- 原“每轮累计读取 Token 额度”已改为“当前模型输入的记忆占用”：每次 BeforeModel 收拢较旧的展开结果，释放下一批读取的空间。同一轮可以继续检索。
- 并行调用仍共享一个待处理批次的额度，防止一次并发结果冲破预算。批次满的提示不会要求等到下一轮用户输入。
- 旧工具结果收拢时保留调用/结果配对；有空间则保留重新打开的 ID，极低预算时清空旧正文。原始归档消息对象不被修改。概览来自独立摘要树。

## 一致性与代价控制

- SQLite 是证据来源，摘要节点是派生缓存。内容、主题、来源标签、状态或时间更正会使受影响的叶子指纹与祖先节点 ID 变化。
- 语义摘要按子节点 ID 缓存，未变化分支可复用。64 条同主题记录中更正 1 条的测试只触发 2 个摘要节点重新生成。
- 父摘要必须返回全部已知子 ID 且不重复，正文非空、不超预算、比合并输入更短。无效输出不会替换有效语义缓存；仍保留结构导航和全部子入口。这个校验不是事实正确性的完整证明。
- 发布根与成员关系使用事务和来源修订校验；构建期间发生更正就拒绝发布混合版本。旧快照失效期间仍可直接检索当前事实。
- 先建立结构覆盖，再后台补充模型摘要。最多同时整理 2 个会话、每批最多 32 次模型调用，90 秒截止，后续请求可复用已完成节点继续整理。前台不等待这些模型摘要调用。
- 初次树准备中使用已有的有预算召回；不会假装摘要树已准备完成。
- 当前结构刷新仍会扫描该会话和 global 的有效记录，并重建成员/路由投影；这部分尚非严格 O(log N) 增量插入。语义摘要缓存与结构维护的复杂度不能混为一谈。
- 新主题插入排序后可能影响跨主题分组；没有声称完成语义最优聚类，也没有大规模性能或真实模型记忆质量评测。

## 测试与边界

- 513 个独立主题：形成多层总树，子节点数不超过 8；多个上下文预算下仍可沿切面覆盖全部原始记录，没有祖先/后代重复。
- 来源更正、跨会话节点读取拒绝、构建中撤回、无效摘要输出、原文仍可读、未改变摘要复用。
- 同一运行连续读取 40 次：每次模型投影记忆不超过 600 Token 测试预算，仍可继续读取；原始结果对象不变。
- 测试模型检查结构与预算，不等于真实模型的摘要质量或信息保持率。
- 主 schema.Message ADK 路径已接入树检索及预算回收。AgenticMessage 路径仍沿用原有有预算注入，尚未接入同一主动树展开工具。
- 所有 Token 上限使用当前统一估算器；整体模型窗口仍由 Session Spine 管理。工具调用协议等框架开销另受整体输入预算控制。
