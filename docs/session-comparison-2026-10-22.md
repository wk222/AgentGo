# 官方 Session、AgentGo 上下文与 Codex 对照

本轮优先修 AgentGo，未新增上游提交。对照依据为本地官方 Eino 修复版本 a21954c09a22、AgentGo 当前源码以及 codex-reference 源码；不是完整能力或性能基准。

| 维度 | Eino 官方 Session | AgentGo 自有实现与当前选择 |
|---|---|---|
| 真正保存什么 | 有身份的模型消息、替换/更新/删除/回滚事件与运行生命周期 | chat_messages 保留界面文本；chat_run_events 记录业务执行；投影负责本轮工作区/记忆/任务。主聊天另由 SQLite 适配官方事件存储 |
| 下一轮如何恢复 | 倒序分页查找有效替换边界，重建活动模型历史；回滚需额外历史证据 | 旧路径只回放最近 24 条、约 24k 字符的用户/助手文本，缺工具协议。新主聊天不再以界面文本重建每轮模型状态 |
| 压缩质量 | 提供触发、摘要、Finalize、事件持久化机制 | 自有目标锚点、用户更正、工具调用/验证状态摘录和预算保护仍有价值；不应删掉后全依赖默认摘要 |
| 工作区感知 | Session 本身不负责理解代码库 | SessionSpine、工作区规则、近期文件、任务与记忆继续由 AgentGo 组装 |
| 中断恢复 | Checkpoint 与 Session 分工；需兼容运行身份与事件序列 | 主聊天接入官方机制，业务审批保留宿主记录。新增 SQLite 重开后的真实工具审批恢复测试 |
| 分支 | 官方有事件回滚语义 | 自有 chat_entries/chat_lanes 目前仅存储/测试层使用，未成为主聊天上下文入口；不能把这当作已经接通的聊天分支（2026-10-30：访问这两张表的 `tree.go` 已删除，只剩遗留空表） |
| 后台任务 | 统一 Manager 和执行接口；持久化取决于 Store 与具体 Executor | 目前后台 Shell 任务表仍在内存，不能承诺崩溃后继续。未知任务不得通过自动重跑冒充恢复 |

结论：官方负责执行事实与重放，AgentGo 负责上下文选择和产品行为。二者职责互补；多套历史各自成为模型事实来源，才容易产生冲突。

## 本轮修复

1. 桌面文本和结构化事件通道共用一个流消费器。工具返回不进入助手正文；非 EOF 断流、取消、事件发送错误会被传播，已经收到的正文随错误返回。
2. 删除会话改为事务：聊天文本、树/分支、原生上下文事件、运行事件、待审批记录、会话模式一起删除。修复 chat_session_modes 表名错误，保留全局默认模式。数据库失败时整体回滚。
3. 已有原生日志的会话初始化只做索引存在性查询，不再复制和序列化不会被采用的旧聊天历史。
4. 压缩开始前和返回后检查父上下文取消；取消不再被当成可忽略的压缩失败，也不会污染重试冷却。
5. Finalize 先检查预计 token 是否实际减少；负收益摘要不能替换原历史。原有当前请求、工具配对与确定性约束摘录继续保留。
6. 修复持久化投影时多个调用方 system 消息顺序反转。新增原生 Runner 重启重放测试验证其各出现一次且顺序一致。
7. RunControl 在所有读写入口统一 agentic: 传输前缀，使停止、追加指令和清理使用同一个会话键。
8. 后台命令输出上限 1 MiB，进度预览最多 512 个 2 KiB 块；无人读取 Updates 时不会堵死 Wait。最终输出返回独立副本。
9. exec 负责排空 stdout/stderr 后再完成 Wait，并设置管道等待上限，避免快速命令丢失尚未读取的输出。
10. 后台恢复找不到原执行时返回“副作用未知”，不自动重跑；已完成 TaskID 重复启动返回已有结果，命令与 TaskID 冲突明确报错。

11. Windows 后台命令改用启动前分组的 Job Object，消除根进程先启动子进程再归组的竞态，并在任务结束时释放 Job 句柄。

## 验证方式

新增断流/EOF/取消、工具 JSON 隔离、SQLite 删除故障注入回滚、外键开启的分支清理、默认模式保留、迁移后跳过序列化、系统消息顺序、负收益压缩、停止键归一、实际子进程 3 MiB 输出、无消费者输出、未知任务恢复和审批跨重启测试。

后台进程树清理在早期全量回归中重复失败，暴露了依赖外部 taskkill 的不稳定性。已改为 Windows Job Object：根进程以暂停状态创建，归入带 KILL_ON_JOB_CLOSE 的 Job 后再恢复初始线程；停止直接 TerminateJobObject，宿主退出时句柄关闭也会结束子进程。非 Windows 继续使用独立进程组。改造后的针对性测试和最终完整回归均通过。

## 与 Codex 仍有差距

- 多种专用编排器还没有统一到隔离的持久化 Session 范围，不能直接共用主聊天事件流。
- 旧会话首次迁移仍受上层旧历史窗口限制；新日志的可靠性不能补回过去从未保存的工具协议或已截断的旧上下文。
- 缺少面向模型、按当前会话范围检索压缩前细节的完整工具。工具输出落盘已有 fetch_spill_content，但所有历史并未统一可检索。
- 上下文估算与实际模型用量反馈、压缩耗时和压缩收益的可见性仍需完善。
- 后台任务的持久化身份、重启后的状态核对、事件日志保留/压缩策略尚需设计；不可用自动重跑或删除旧事件来伪造恢复。

本轮没有声称达到 Codex 完整水平；先把成功、失败、取消、未知与恢复的边界做实，再扩展检索与长任务能力。
